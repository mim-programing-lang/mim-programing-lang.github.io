Try 0.17.3 with us

Meem 0.17.3 is the beta before 1.0, together with the Meem editor 0.5.0 (which has Meem 0.17.3 built in). The aim is for many people to write real programs in Meem on their own machines, so that what automated testing misses comes to light before the language is frozen in 1.0. Between 0.10.0 and 0.17.3 the language changed a lot, and some of the changes break 0.10 programs. Download it from the download page.

What changed since 0.10.0

Section titled “What changed since 0.10.0”
  • 0.11: a string cannot be لاشيء (nothing); absence is an optional type ن؟, checked before use; and an error has context («نشأ في», originated in, a cause and a message). Migration
  • 0.12 (breaking): sized numbers: عدد and كسر were removed, you write عدد64 and كسر64, and conversion is explicit (حلل(ن, عدد64)). Migration
  • 0.13: the compiler frees temporaries by itself, and --debug-mem=fail. Migration
  • 0.14: tuples and destructuring, enum values and widths, line-by-line reading, binary files and byte strings, and the confirmed leak E0472 is a compile error. Migration
  • 0.15 and 0.16: enums with a payload, and generic functions, structs and enums. Migration
  • 0.17 (breaking): traits and constraints (سمة and يحقق are reserved words), the مجموعات (collections) library, and --strict-memory; and the warning policy: thirteen warnings became compile errors, and what the compiler cannot prove is behind --warn-unproven. Migration
  • 0.17.1 to 0.17.3: handbook corrections, free functions in مجموعات, and == on an enum with a payload that does not implement قابل_للمساواة is now a compile error (E0536) instead of a silent wrong result.

Every change is in the changelog, and the new lessons: tuples, generics and traits, and the collections library.

What we ask you to test

Section titled “What we ask you to test”

In order, most important first:

  1. Installing and running on your machine: unpack the archive, then meem --version, the self-test (meem --self-test), and meem build, on any Linux x86_64 with glibc 2.35 or newer. The package was tested on Debian 12 and Ubuntu 22.04 only, so every other distribution (Fedora, Arch, openSUSE, Mint…) is a new trial.
  2. Real programs: a small tool you need (processing a text file, a calculation, a terminal game), not the handbook’s examples. What matters: can it be written in Meem as you expect, and where did you have to work around something.
  3. Error messages: when the compiler rejects your program, does the message say what the error is and where, and does the hint fix it? An unclear message deserves its own report.
  4. The newest parts of the language: sized numbers and the optional type, tuples, enums with a payload, generics and traits, and memory (E0472, --warn-unproven, --strict-memory and the detector): can you write what you want with them, and does the message point you to the line? And does the output of meem برنامج.م differ from --release?
  5. The standard modules: ملفات (with the reader, the writer and binary files), نظام, مسارات, رياضيات, عشوائي and مجموعات, on Arabic and large files and paths.
  6. meem build: does the built file run on another machine that has no Meem?
  7. The tools: --check --json and --fix, for anyone writing a tool or an editor plugin (the tools contract).

Not needed: precise performance, and behaviour inside خطر (which is undefined anyway).

How to report a bug

Section titled “How to report a bug”

Reports go in the meem-feedback repository on GitHub (you need a GitHub account), one report per bug. It has a «بلاغ خلل» (bug report) form with the same fields as the template below, and a «اقتراح» (suggestion) form; the forms are in Arabic. Before you write: search the open reports, and «what is already known» at the bottom of this page.

Open a report or a suggestion · Open reports

The report template

Section titled “The report template”

Copy it as it is into the body of the report, and fill in every section (write «not applicable» rather than deleting a section):

What you attach Why
meem --version It holds the commit (such as 0.17.3+abcdef0), which identifies the exact package
The system and glibc The package was tested on Debian 12 and Ubuntu 22.04 only
The program as text (the .م file, not a screenshot) To reproduce the bug; a smaller program is fixed faster
stderr and the exit code The most important part is the message’s ID (E0123 in [خطأ دلالي E0123]), explained in the error catalog
--check --json The full diagnosis with its position and ID

Report categories, by what you see (the category tag goes in the title, in Arabic):

What you see Category (in the title) Priority
«خطأ داخلي في المجمّع» (internal compiler error) or a Python traceback [داخلي] (internal) Top
The program crashes with a signal (SIGSEGV, code 139) outside خطر [سقوط] (crash) Top
Output that contradicts the handbook, or a correct program rejected [ناتج] (output) High
meem build gives output different from a direct run [بناء] (build) High
A message that cannot be understood, or a hint that leads to another error [رسالة] (message) Medium
Something hard to write in Meem [لغة] (language) Collected for the 1.0 decision

Privacy: the compiler sends nothing anywhere. But a report on GitHub is public, so remove from the program and the output whatever you do not want published: paths with your name in them, secrets in environment variables, and real data.

What is already known (no report needed)

Section titled “What is already known (no report needed)”
Known Details
Linux x86_64 only, and glibc 2.35 or newer No macOS, Windows, ARM or musl distributions, and not in 1.0 either
The licence The Meem License (version 1.0), and its text is inside the package: in the compiler’s folder since 0.9.1 (LICENSE and LICENSE.en), and in both editor packages since 0.4.0 (/usr/share/doc/meem-editor/) and the «About» window
The AppImage does not register the file type with the system No icon for .م files and no association with the editor, except with the deb package
Strings are sorted by code point No Arabic dictionary order
No untagged اتحاد (union), no pointer arithmetic, and no dynamic polymorphism After 1.0 (generics and enums with a payload exist since 0.15–0.16)
No JSON, networking or running commands in the library Not before 1.0, and خارجي to C is available
A named string in a long loop stays until exit if it is not freed A temporary without a name is freed by itself since 0.13.0; a named one is mentioned by --warn-unproven (E0471), and خاتمه حرر(ن) gives it back (memory in long loops)
A built file without the detector Use after free through another name is undefined behaviour in it (old output or garbage), and a double free through another name crashes it. A direct run and meem build --debug catch both
Growing with ن += ذيل leaves the old buffer behind A documented, bounded leak: about the base-2 logarithm of the length in buffers, totalling about twice the final length
حرر does not follow what is inside a container A list of lists, or a list of strings from تقسيم: use an arena for nested structures
The detector is slower A direct run is 0% to 32% slower than --release on the benchmark programs, and memory freed in its mode is not returned to the system
A call chain deeper than 2000 to 3000 consecutive functions Compile error E0385 «أعقد مما يدعمه المجمّع» (more complex than the compiler supports), not a crash; a documented limit that stays
A huge file is slow to compile 50 thousand lines (5000 functions): --check in 8 s, and running or building in 66 s with 1.4 GB of memory
No CPU or memory limit in the compiler A program runs with the user’s full permissions (what a program can do on your machine); the options --no-system, --no-ffi and --no-unsafe restrict it
Fixed in 0.11 to 0.17.3 Line-by-line reading and binary files (0.14); double-clicking a .م file in GIO-based file managers (GNOME) is recognised as text/x-meem since Meem editor 0.5.0; and == on an enum with a payload without يحقق قابل_للمساواة used to return خطاء silently and is now E0536 (0.17.3)
Fixed in 0.10.0 The crash from using a list or dictionary after حرر (now E0428), and the hidden copies from views
Fixed after 0.8.0 A string too big for memory used to crash the program (now «نفدت الذاكرة», out of memory, E0427), and a very deep call chain used to be an «internal error»

When 1.0 comes

Section titled “When 1.0 comes”

1.0 comes when all of these hold:

  1. At least four weeks after the next beta release.
  2. At least five testers besides the project’s owner.
  3. At least three distributions on which the package was tried.
  4. No open report of top or high priority ([داخلي], [سقوط], [ناتج] and [بناء]).
