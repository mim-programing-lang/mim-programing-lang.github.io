ميم أقرب إلى Zig من أي لغة تعليمية: المخصص قيمة تُمرَّر، و`خاتمه` تقابل `defer`، و`!نوع` تقابل `!T`. ولم يكن Zig مثبتاً على جهاز التحليل، فما يخص Zig هنا من وثائقه، **غير مجرَّب**.

## ما يقابل ماذا

| في Zig | في ميم |
|---|---|
| `std.mem.Allocator` يُمرَّر | المخصص وسيطاً أخيراً، ويجوز تركه فيُمرَّر `الافتراضي` |
| `ArenaAllocator` | `ساحة(الاصل)` و`اعد` |
| `FixedBufferAllocator` | `مخزن_ثابت` |
| `GeneralPurposeAllocator` في التنقيح | `كاشف(...)`، أو `--debug-mem` للبرنامج كله |
| `defer` / `errdefer` | `خاتمه` / `خاتمه_عند_خطأ` |
| `!T`، `try`، `catch` | `!نوع`، `جرّب`، `والا` |
| `error{...}` | كتلة `اخطاء:`، ومجموعة واحدة عامة |
| `?T` | `لاشيء` للنص والمؤشر فقط |
| Debug / ReleaseSafe / ReleaseFast | الفحوص دائماً، و`بلا_فحص` داخل `خطر` موضعياً |

## أين تخالف ميم نموذج Zig (0.9.1)

- **«لا حجز مخفي» ليست قاعدة:** تمرير «عرض» (`جزء`، `قص_الفراغات`) إلى `طول` أو `==` يحجز نسخة لا تُعاد.
- **الشريحة والنص:** النص `{مؤشر، طول، مالك}`، لكن وقت التشغيل يحتاج الصفر في آخره في عمليات كثيرة، وهذا سبب النسخ.
- **لا `comptime` ولا أنواع معمّمة.**
- **`خاتمه ... والا` غير ممكنة:** التنظيف الذي قد يفشل يحتاج دالة غلاف.
- **لا مخصصات يكتبها المستخدم**، ولا `resize` ولا محاذاة.
- **كاشف الذاكرة لا يرى الاستعمال بعد التحرير للنص والقائمة** إلا بأثره، وقد يخفي العرض المعلَّق.
- **الخطأ بلا مجموعات في التوقيع ولا تتبّع** (Zig له error return trace في التنقيح).
