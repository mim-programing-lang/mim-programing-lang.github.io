## Step by step

1. **Arguments:** `اقرأ_الوسائط` returns `!قائمة[نص]`, and its error is `استعمال_خاطئ` (wrong usage) from the `اخطاء:` block. `رئيسي` (main) handles it with `والا خ:` and prints how to use the program.
2. **Reading:** `جرّب ملفات.اقرأ_سطور(مسار)` reads the whole file as lines, and the `خاتمه حرر(سطور)` next to it gives the list back on exit.
3. **Counting:** each line is split into pieces with `تقسيم`, `نظف` removes punctuation from the end of a word with `جزء`, and the dictionary `عداد` counts.
4. **Sorting:** `رتب_ب(مدخلات, قبل)` with a comparison function: the most frequent first, then alphabetical order.
5. **Printing:** `رياضيات.نسق_عدد` aligns the columns to a fixed width.

## What was hard

- **The hidden cost (in 0.9.1):** `نظف` uses `جزء` because it is a «view» with no copying. But in 0.9.1, `طول(ن)` on the view inside the loop allocated a small copy every time, never given back and not visible in the code, and that only showed up with `--debug-mem`. **In 0.10.0**, operations on a view allocate nothing.
- **Memory:** on a 9 MB file, the built program's peak was 69.6 MB, against 10.7 for the equivalent Python program: Meem reads the whole file and its lines into memory (there was no line-by-line reading before 0.14.0), and on top of that came the hidden copies in 0.9.1. This measurement has not been redone since 0.9.1.
- **Time:** 0.70 s built statically, 0.56 s built with `--dynamic`, and Python 0.74 s.

## What we learned

- Errors are values: forgetting to handle `!قائمة` is a compile error, so the program never reaches run time with a neglected failure.
- `خاتمه حرر(...)` next to the allocating line is enough in simple cases, and `--debug-mem` tells you which line did not free.
- In a long loop over strings from `جزء`, compute `طول` once and keep it.
