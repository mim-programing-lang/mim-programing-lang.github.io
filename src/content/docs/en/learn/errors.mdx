## Goal

To write a function that can fail, and to handle its failure: with a fallback value, with a block that knows the reason for the error, or by passing it on to the caller.

## Explanation

- A function that can fail writes `!` before its return type: `!عدد64`. When it fails, it returns `خطأ.اسم` (error.name).
- You define the names of your errors in an `اخطاء:` (errors) block at the top of the file.
- `ن = ف() والا 0`: if it fails, the value is 0. And `والا خ:` followed by a block: inside it, `خ` is the error's name, and the last line of the block is the fallback value.
- `جرّب ف()` (try) inside a `!نوع` function: if `ف` fails, your function exits with the same error.
- Forgetting to handle it is a **compile error**: your program never reaches run time with a failure you have not decided what to do with.

`جرّب` passes the first failure to whoever called the function:

<Example file="lessons/15_جرب.م" title="جرّب" />

**An error has context** (since 0.11.0): the library's errors carry what happened, so `اطبع(خ)` prints for example «صيغة_خاطئة: «ثلاثون» ليس عدداً» (wrong format: «ثلاثون» is not a number), or the path and the system error number for a file error; `ارجع خطأ.اسم مع قيم` attaches a message to your error, and `بسبب خ` (because of) the error that came before it. A signature may list its errors: `!{غير_موجود, ممنوع} نص`. Details in [error handling](/en/docs/language/errors/). Runtime errors, such as division by zero or an index outside the list, are not of this kind: they cannot be handled, and they end the program with code 3. Details in [dealing with errors](/en/docs/understand/errors/).
