ميم تُترجم مثل C إلى شيفرة آلة (عبر LLVM)، وذاكرتها يدوية. لكنها تفحص الحساب والفهرسة دائماً، وتكتب الأخطاء قيماً في التوقيع.

## ما يقابل ماذا

| في C | في ميم |
|---|---|
| `int64_t`، `double`، `bool` | `عدد` (64 بت بإشارة)، `كسر`، `منطقي` |
| `char *` منتهٍ بصفر | `نص`: UTF-8 بطوله، و`طول` يعدّ **الأحرف** لا البايتات |
| `struct` | `هيكل`: يُمرَّر بالقيمة |
| مصفوفة ثابتة / مصفوفة تنمو | `مصفوفة[نوع, حجم]` (تُنسخ عند الإسناد) / `قائمة[نوع]` |
| `malloc` / `free` | الحجز من مخصص (ضمني في الغالب) / `حرر(س)` |
| `T *` و`NULL` | `مؤشر[نوع]` بـ `جديد` و`محتوى`، و`لاشيء`؛ **لا حساب عناوين** |
| `void *` من مكتبة | `مؤشر_خام`، ولا يُقرأ إلا داخل `خطر` |
| رمز إرجاع و`errno` | `!نوع` و`خطأ.اسم`، ومعالجته إلزامية |
| `goto cleanup` | `خاتمه` و`خاتمه_عند_خطأ` |
| `#include` | `استورد` |
| `printf` | `اطبع` بالفواصل، و`رياضيات.نسق` و`نسق_عدد` للتنسيق |
| تجاوز غير معرَّف | خطأ تشغيل برمز 3 (و`--wrap-overflow` للالتفاف) |
| استدعاء مكتبة C | `خارجي` بأنواع C صريحة |

## ما سيفاجئك (من تجربة كتابة برامج حقيقية بـ 0.9.1)

- **قائمة أو قاموس بعد `حرر` بالاسم نفسه يُسقط البرنامج**، وعبر اسم آخر يطبع بيانات خاطئة بلا خطأ. والعمر غير مضمون إلا ما يكشفه `--debug-mem`.
- **نسخ خفية:** `طول` و`==` وغيرهما على «عرض» (ناتج `جزء`) تحجز نسخاً لا تُعاد.
- **لا بايتات:** `طول` و`جزء` بالأحرف، ولا نوع «بايتات».
- **لا أنواع معمّمة:** الكومة تُكتب لنوع واحد.
- **`هيكل_سي` يُعرَّف قبل التصريح الذي يستعمله**، والخطأ الأول قد تتبعه رسائل مضلِّلة.
- **الخطأ اسم بلا بيانات**، ولا تتبّع لمساره.
- **لا `printf` ولا دوال بعدد متغير من الوسائط**، ولا هياكل بالقيمة إلى C.
- **البناء الساكن (musl) أبطأ** من `--dynamic` في البرامج الكثيرة الحجز.

## وما سيعجبك

- الحدود والتجاوز مفحوصة افتراضياً، برسالة بالسطر والمعرّف.
- `خاتمه` و`خاتمه_عند_خطأ` بترتيب صحيح عبر الدوال.
- ملف تنفيذي ساكن بعشرات الكيلوبايتات، يُبنى في نحو ثانية.
- أداء الشيفرة الخوارزمية بمستوى C ([دايكسترا وشجرة بحث](/learn/projects/algorithms/)).
- `خارجي` سطر لكل دالة، والرمز يُفحص عند الترجمة.
