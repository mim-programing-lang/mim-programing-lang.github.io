## Goal

To write a function that can fail, and to handle its failure: with a fallback value, with a block that knows the reason for the error, or by passing it on to the caller.

## Explanation

- A function that can fail writes `!` before its return type: `!عدد`. When it fails, it returns `خطأ.اسم` (error.name).
- You define the names of your errors in an `اخطاء:` (errors) block at the top of the file.
- `ن = ف() والا 0`: if it fails, the value is 0. And `والا خ:` followed by a block: inside it, `خ` is the error's name, and the last line of the block is the fallback value.
- `جرّب ف()` (try) inside a `!نوع` function: if `ف` fails, your function exits with the same error.
- Forgetting to handle it is a **compile error**: your program never reaches run time with a failure you have not decided what to do with.

**Limits today (0.10.0):** an error is only a name, with no data attached (no «which line» and no «which file»), and a function's signature does not say which errors it returns. Runtime errors, such as division by zero or an index outside the list, are not of this kind: they cannot be handled, and they end the program with code 3.
