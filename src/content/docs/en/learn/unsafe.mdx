## Goal

To call a function from a C library, and to know what can only be written inside a `خطر` block, and why.

## Explanation

- `خارجي` (extern) declares a function from a C library with explicit C types; then you call it like any function. At compile time, the compiler checks that the symbol exists.
- `طول("ميم")` counts characters (3), while `strlen` from C counts bytes (6): an Arabic letter is two bytes in UTF-8.

<Example file="lessons/17_خارجي.م" title="Two functions from C" />

- Raw memory (`احجز_خام`), raw pointer indexing, and switching checks off (`بلا_فحص`) can only be written inside `خطر:`. There the compiler does not check bounds, and mistakes are your responsibility.

<Example file="lessons/17_خطر.م" title="Raw memory inside خطر" />

- **A beginner does not need it:** lists, dictionaries and the standard modules are enough for most programs. And `خطر` keeps whatever might corrupt memory in blocks you can see and review.
- The `--no-unsafe` option forbids `خطر` entirely, and `--no-ffi` forbids `خارجي`.
