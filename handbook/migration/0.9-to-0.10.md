# الترحيل من 0.9 إلى 0.10

المصدر: [../../../CHANGELOG.md](../../../CHANGELOG.md) (قسم 0.10.0). قبل 1.0 يحمل الإصدار الثانوي التغيير مع إعلانه هنا وفي
السجل ([../../deprecation-policy.md](../../deprecation-policy.md)). البرنامج الصحيح، أي الذي لا يستعمل ذاكرة بعد تحريرها،
يبقى بالناتج نفسه.

## ما يتغير

| كان في 0.9 | صار في 0.10.0 | ما تفعله |
|---|---|---|
| `meem برنامج.م` بلا كاشف، و`--debug-mem` للكاشف وتقريره | الكاشف افتراضي في التشغيل المباشر، بلا تقرير؛ و`--debug-mem` يضيف التقرير عند النهاية | لا شيء. ولقياس الأداء بالتشغيل المباشر، أو لبرنامج يحجز كثيراً ويطول عمله، أضف `--release` |
| `meem build` بلا كاشف، و`--debug-mem` يبنيه به | كما هو، و`--debug` يبنيه به أيضاً | لا شيء |
| `--debug`: تفاصيل الخطأ الداخلي في المجمّع | الكاشف أيضاً | أداة تمرّر `--debug` لتتبّع خطأ داخلي تحصل على الكاشف معه |
| استعمال نص أو قائمة أو قاموس بعد تحريره عبر اسم آخر: ناتج قديم أو نفايات برمز 0 | خطأ تشغيل `E0429`/`E0430` برمز 3 في التشغيل المباشر | أصلح البرنامج: الخطأ كان فيه. وفي الملف المبني بلا كاشف يبقى سلوكاً غير معرَّف |
| قائمة أو قاموس بالاسم نفسه بعد `حرر`: سقوط SIGSEGV | `E0428` برمز 3 في كل الأوضاع | كما سبق |
| نص يُمرَّر إلى دالة `خارجي` تحتفظ بعنوانه بعد رجوعها (`putenv`) | إن كان عرضاً (لا يتلوه صفر) فالنسخة تُعاد بعد رجوع C | مرّر `نص_سي(ن)` واحتفظ به ما احتفظت به C |

## مثال

```
ق = [1, 2, 3]
ب = ق
حرر(ق)
اطبع(ب[0])
```

في 0.9.1 يطبع `1` (ذاكرة محرَّرة) برمز 0. وفي 0.10.0:

```
[خطأ تشغيل E0429] سطر 4:7 - استعمال القائمة أو القاموس بعد التحرير (أُنشئت في السطر 1 وحُرّرت في السطر 3)
  اطبع(ب[0])
```
