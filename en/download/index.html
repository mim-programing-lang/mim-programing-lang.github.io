The compiler meem

The command that builds Meem programs into standalone executables, and runs them directly for trying things out. Linux x86_64.

Meem editor

An editor in which you write Meem from right to left, with the compiler 0.17.3 built in, so you do not need to download the compiler separately. Linux x86_64, as deb and AppImage.

Files

Linux x86_64 only. Windows and macOS are not available in 1.0.

Check the download

After downloading, make sure the file did not change on the way: compute its SHA-256 fingerprint (a digital fingerprint that changes if a single byte of the file changes) and compare it with the fingerprint written here.

sha256sum file-name

Or let the tool compare for you: put the fingerprint and the file name on one line, separated by two spaces, and pass it in:

echo "fingerprint  file-name" | sha256sum -c

If it prints OK, the file is intact. If it prints FAILED, do not run it; download it again.

0.17.3 is a beta release

Meem 0.17.3 is the beta before 1.0, and Meem editor 0.5.0 includes the same 0.17.3 compiler. Between it and 0.10.0 there are changes that break 0.10 programs: sized numbers (عدد64 instead of عدد), the optional type, and the warning policy. What changed is in the changelog and the migration pages. What we ask you to test, and how to report a bug: Try 0.17.3 with us.

Requirements

Section titled “Requirements”
  • Linux x86_64. Windows and macOS are not available in 1.0.
  • glibc 2.35 or newer (glibc is Linux’s core C library): Ubuntu 22.04, Debian 12, and later. The packages do not run on anything older (Ubuntu 20.04, Debian 11).
  • The compiler needs neither Python nor a C compiler nor a linker. Unpacking the archive needs xz-utils, which is usually installed on desktop systems; otherwise install it: sudo apt install xz-utils.
  • The editor as a deb (an Ubuntu and Debian package) depends on libwebkit2gtk-4.1-0 and libgtk-3-0 from the distribution’s repositories, and apt installs them with it.
  • The editor as an AppImage (a single file that runs without installation) needs libfuse2, or running it with the option --appimage-extract-and-run.
  • The file the compiler builds is static and needs nothing on the machine that runs it.

Installing and running

Section titled “Installing and running”

The compiler

Section titled “The compiler”

Unpack the archive in any folder, then run meem from inside it. It needs no installation and no administrator rights:

The folder can be moved as it is, and nothing is written into it when it runs. It holds the licence text: LICENSE (the Arabic text, which is the authoritative one) and LICENSE.en (its English translation, for guidance), and the licences of the bundled components in the licenses/ folder. Next step: getting started.

Meem editor (deb)

Section titled “Meem editor (deb)”

For Ubuntu and Debian:

Then open «محرر ميم» (Meem editor) from the applications menu, or run it with the command meem-editor. To open a file: meem-editor ملف.م; if the editor is already running, the file opens in its window. The package holds the licence text: /usr/share/doc/meem-editor/LICENSE (the Arabic text, which is the authoritative one) and LICENSE.en, and the Arabic text is in the «About» window.

Meem editor (AppImage)

Section titled “Meem editor (AppImage)”

For any distribution with glibc 2.35 or newer and the interface libraries:

If the message «Cannot mount AppImage» appears, install libfuse2, or run it with ./meem-editor_0.5.0_amd64.AppImage --appimage-extract-and-run.

Known issues

Section titled “Known issues”
  • The AppImage does not register the .م file type with the system: no icon for these files, and no association with the editor. That comes with the deb package only.
  • The detector makes a direct run slower (0% to 32% on the benchmark programs) and heavier on memory. For measurements, run with --release, or with the «تشغيل سريع (–release)» (fast run) button in the editor.
