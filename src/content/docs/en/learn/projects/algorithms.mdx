**The idea:** a 400×400 grid with random weights (fixed seed 42): the shortest path from corner to corner with Dijkstra and a min-heap. Then a binary search tree with 200 thousand insertions, its height, and freeing all of it.

## Step by step

1. **A min-heap on top of a list:** `ادفع` (push) adds at the end then raises the element until it settles, and `اسحب` (pop) takes the smallest and moves the last one down in its place. The elements are `عنصر_كومة` structs, by value.
2. **Dijkstra:** a list `بعد` of distances, a heap of candidates, and the four neighbours in a fixed `مصفوفة[عدد64, 4]` (-1 for a missing one).
3. **The tree:** a node holds `مؤشر[عقدة_شجرة]` pointers to the left and right. `جديد(...)` (new) allocates a node, `محتوى(م)` (content) reaches it, and `لاشيء` (nothing) for an empty one.
4. **Deep freeing:** `حرر` does not follow pointers, so `احرق` walks the tree and frees each node by hand.
5. **Time:** it prints «صواب» (true), not the seconds, so that the output stays the same.

## What was hard

- **No generic types:** the heap works for `عنصر_كومة` only; for another type the code is copied (or the list holds indices into another list). Generic types come after 1.0.
- **Deep freeing is manual:** nothing frees the tree except `احرق`.
- **The `--debug-mem` report** attributed a list's growth to a line in the standard library (`عشوائي.م`), not to a line of the program.

## What we learned

- **Performance on a par with C:** in the report, 0.27–0.31 s for the built file, against 0.29 s for a C version built with `gcc -O2`, and a peak of 8.6 MB.
- Pointers in Meem are simple and need no `خطر`: `جديد`, `محتوى` and `حرر`, and a check for `لاشيء` before access.
